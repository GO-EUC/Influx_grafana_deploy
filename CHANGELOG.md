# Changelog

## Unreleased

### Added
- **Web ports:** the web server (nginx) can use the standard ports 80/443 or the alternative 8080/4443. Switch on the landing page (*Maintenance → Web ports*), with `sudo go-euc-set-ports standard|alternative`, or before first boot with `APPLIANCE_HTTP_PORT` / `APPLIANCE_HTTPS_PORT`. The Telegraf configs, `config.txt` (new `HTTPPort` / `HTTPSPort` entries), the install summary and the Proxmox Metric Server settings follow the change, and `go-euc-status`, `go-euc-change-ip` and `go-euc-migrate` (`<old-ip>:<port>`) know about it.
- **InfluxDB API at the root** of the web port (`https://<appliance>/api/v2/...`, token required), for tools that take a host and port instead of a URL, such as OBUX and the InfluxDB client libraries.
- **Testing section (GO-EUC/benchmarkle)** on the landing page: save an Anthropic API key (credentials and `config.txt`) and a GitHub token (root-only); **set up your environment** in the benchmarkle repository (InfluxDB `OBUX` bucket and a read/write token for Tests, Performance and OBUX; secrets `INFLUXDB_TOKEN`, `ANTHROPIC_API_KEY`; variables `INFLUX_URL`, `INFLUX_ORG`, `OBUX_EMAIL`); **Azure** device sign-in and benchmarkle's `Setup.ps1`; **run a research** (validate only by default) and see recent runs. Backend `go-euc-benchmarkle`; PowerShell 7, Azure CLI and GitHub CLI are installed during first boot and updated by the full update. See `docs/testing-with-benchmarkle.md`.
- **GO-EUC branding on the landing page:** the go-euc.com look (dark theme, lime accent, Inter, GO-EUC logo and favicon). Same sections and functions as before.
- **Public host name** (*Maintenance → Public host name*, `sudo go-euc-set-hostname <name>[:<port>]`, or `APPLIANCE_PUBLIC_HOSTNAME`): the name clients are given in the Telegraf downloads, the Proxmox Metric Server settings and Grafana's links, with or without a Let's Encrypt certificate, e.g. behind a reverse proxy.
- **Grafana links use the Let's Encrypt domain.** Once a certificate is active, Grafana's own URL becomes `https://<domain>/grafana/` (with `:4443` on the alternative ports), so share links and alert notifications no longer point at `http://localhost/grafana/` (`go-euc-grafana-url.sh`, run by the certificate's deploy hook and kept by the installer).
- **[External access guide](docs/external-access.md):** DNS, port forwarding straight to the appliance, through a reverse proxy (one public IP shared with other services), or on the alternative ports; what's exposed; Let's Encrypt troubleshooting. The architecture page shows the three setups.

## v2.0 (2026-11-25)

Major release. Existing appliances move to it by deploying a new appliance and running `sudo go-euc-migrate <old-ip>` on it (see `docs/switching-appliances.md`).

### Security
- **Command injection fixed.** Anyone who could reach the appliance could run commands as root through the Let's Encrypt email field. Email and domain validation is now strict, and every value written to `/etc/go-euc/config.env` (wizard, web API) is shell-quoted.
- **Login required** (the `goeucadmin` appliance login, HTTP basic auth) for the landing page, `/telegraf/` and `/api/`.
- **`config.txt`** still lists every credential, but nginx serves it without a login only to the appliance's local IPv4 subnet(s); everyone else gets 403. The file is mode 640 (root and the nginx container). The subnet list is generated by `go-euc-local-access.sh`.
- **Break-glass password**: random per build and rotated per VM on first boot. It's shown on the console banner only while setup is pending or has failed. The console wizard now requires a new `goeucadmin` password (8+ characters, not the default).
- **SSH password authentication** is only enabled after the wizard has replaced the default password.
- **Write-only InfluxDB tokens**: Telegraf clients and collectors get a token that can only write to `Performance`; Proxmox Metric Server gets one that can only write to `Proxmox`. The admin token is no longer distributed.
- **Fewer open ports**: InfluxDB (8086) and Grafana (3000) are bound to localhost and reached through nginx; Portainer's edge port 8000 is no longer published.
- **Secrets and files**: secrets come from a cryptographically secure source. The install log and credential files are root-only (600), and the full credential summary is no longer appended to `/etc/issue`.
- **Pinned container images**: Grafana `13.3`, Portainer `2.45.4`, `goeuc/webserver:2004.01`, Telegraf `1.40`; InfluxDB `2.7` and nginx `1.27-alpine` as before.

### Fixes
- **`/telegraf/` returned 403 Forbidden** after signing in in the first v2.0 build: nginx had no directory listing for the folder, so the landing page's *Browse /telegraf/* link and the Windows install guide led nowhere (individual files still downloaded). `/telegraf/` now shows a file listing behind the same login. v2.0 was re-released with this fix.
- **Telegraf configs** didn't parse: the `token` line was missing its closing quote, and the `TELEGRAG` placeholder was misspelled.
- **Telegraf TLS**: configs set `insecure_skip_verify = true` while the appliance uses its self-signed certificate. Once Let's Encrypt is active, they switch to the domain with full verification (`go-euc-publish-telegraf-config.sh`).
- **Long-running actions**: nginx no longer times out `/api/` calls after 60 s, and the API server handles requests in parallel.
- **InfluxDB uploads**: nginx accepts write batches up to 32 MB on `/influx/` (Proxmox Metric Server sends up to 25 MB).
- **Full update** no longer re-runs the whole installer every time; the compose detection pattern was wrong.
- **Let's Encrypt renewals** from `certbot.timer` are now applied to nginx by a deploy hook.
- **Dashboards**: `Dashboards.zip` no longer includes `__MACOSX` files, and extraction skips them.
- **CI** publishes `Dashboards.zip` to the Azure `files` container on `main` and bakes its URL into each image, so appliance updates match the repo.

#### Found by the first end-to-end test on Nutanix AHV (`testing/`)
- **InfluxDB API through `/influx` didn't work.** InfluxDB 2.7 has no base-path setting (`INFLUXD_HTTP_BASE_PATH` was silently ignored), so every `/influx/...` request reached its web UI and got a 200 HTML page. This broke Telegraf clients (`https://<ip>/influx`), the collectors and the Proxmox Metric Server push without any visible error; the install health check was fooled the same way. nginx now strips the `/influx` prefix for the API. InfluxDB's UI and API are served over TLS on `https://<ip>:8086/`, and the container is no longer published on the host. Collectors write to `http://influxdb:8086` directly, and the installer checks health with `influx ping`.
- **Every `/api/*` call returned 502**, so no landing-page button or form worked. nginx tried to reach the API backend on the Docker gateway while it only listened on `127.0.0.1`. nginx now uses a Unix socket shared only with its container (mode 660, nginx group), so the backend still never listens on the network.
- **`/portainer/` returned 404.** Portainer's `--base-url` only changes generated links, so nginx now strips the prefix, and it adds WebSocket headers for container consoles.
- **Collector configs failed under Telegraf 1.38+ strict environment handling**, which only substitutes variables inside quoted strings and inserts them raw. Collector env files now carry raw values (TOML-escaping them added stray backslashes to passwords). TLS verification is written into each config when the collector starts.
- **One dashboard was never provisioned.** `GO-EUC-Windows-Process-Analysis.json` was a bare Grafana v2 spec, which file provisioning rejects. `go-euc-grafana-dashboards.py` wraps such exports into full `dashboard.grafana.app/v2` resources when the bundle is extracted.
- **An unreachable vCenter looked healthy.** The vSphere plugin only connects on its first collection, after the startup check. Collectors now run a pre-flight check before starting (vCenter reachability and TLS; Prism Element login), so wrong addresses fail in seconds.
- **Troubleshooting dashboard** (previously only in the published bundle) is now in the repo's `Dashboards.zip`, with its data source resolved to `DS_GO` (its `${DS_DS_GO}` placeholder had left its panels without a data source). Extracted dashboards are made readable for Grafana whatever permissions the zip records.
- **Duplicate dashboard title**: the Test Runs dashboard was titled "GO-EUC: Windows Process Analysis"; it's now "GO-EUC: Windows Process Test Runs".

- **Portainer admin never created.** Portainer 2.45 requires a one-time setup token for the first admin, so the installer's request was rejected (403) and Portainer locked itself after 5 minutes ("timed out"). The installer now reads the token from Portainer's log, checks for an existing admin, retries after a restart if needed, and no longer passes the password on the command line.
- **`config.env` service overrides were ignored** (`INFLUX_ADMIN_ORG`, the admin users/passwords): first boot never passed them to the installer. They're now exported.
- **SSH password login never worked**, although first boot tried to enable it: the Ubuntu cloud image's `sshd_config.d/60-cloudimg-settings.conf` (`PasswordAuthentication no`) takes precedence over `sshd_config`. A `10-go-euc.conf` drop-in now enables it after the wizard. Appliances from earlier releases only accept SSH keys.
- **First-boot internet check took ~12 minutes to give up** with an unreachable DNS server (sequential 10 s probes). It now probes in parallel with a 2-minute deadline and shows "Waiting for internet access (attempt N)" on the banner. The banner also shows the configured DNS servers instead of the local stub `127.0.0.53`.
- **`go-euc-status` flagged collectors after updates and reboots**: it counted the brief write errors while InfluxDB restarts, which Telegraf retries without data loss. Those are now ignored.
- **Packages installed before the static IP was applied.** First boot installed packages before configuring the network, so on networks without DHCP those installs failed silently. The network is now configured first.

### Features
- **Infrastructure collectors**: Telegraf containers on the appliance, each configured from its own landing-page card, managed by `go-euc-collector.sh`, and refreshed by updates:
  - **VMware vSphere**: realtime VM/host metrics every 20 s, historical cluster/datastore/datacenter every 5 min.
  - **Nutanix Prism Element**: `nutanix_host` from the Prism Element v2.0 hosts API, one series per host (the original Windows config only recorded the first host).
  - **Proxmox VE**: discovers every node through the API. Collects per-VM/LXC stats (`inputs.proxmox`), node status, 1-minute node history (network throughput, ZFS ARC, pressure stalls), every cluster resource including storage, and quorum.
- **Proxmox Metric Server target**: a `Proxmox` bucket and write-only token. The Proxmox card shows the settings and a ready-made `pvesh` command.
- **Landing page** reorganised into Services, Infrastructure collectors, Telegraf for Windows, Maintenance, Certificates and an Activity panel.
- **Windows Telegraf templates** for Nutanix Prism Element and Proxmox VE, alongside the vSphere one.
- **Unattended deployment**: cloud-init can pre-seed the console wizard's answers (see README, "Unattended deployment").
- **First-boot internet check**: stops with a clear `FAILED: No internet access` banner, naming the unreachable sites, instead of failing partway through.
- **`go-euc-status`**: one command for setup state, network, services, containers, collectors, endpoint health, recent errors and log locations.
- **`go-euc-migrate <old-ip>`**: switch to a new appliance with one command on the new appliance. It copies every InfluxDB bucket over the API (into the new org, keeping the new tokens) and hand-made Grafana dashboards; the old appliance is only read. Guide: `docs/switching-appliances.md`.
- **`go-euc-change-ip`**: change the static IP after setup (e.g. take over the old appliance's address); refreshes the `config.txt` subnet list, the Telegraf downloads and the banner.
- **`go-euc-backup.sh` / `go-euc-restore.sh`**: file-based backup and restore of InfluxDB data, collector settings, carry-over settings and optionally Grafana's database.
- **Releases on demand**: pushes to `main` no longer create a release automatically. Run the build workflow on `main` with **Create release** and choose a **major** or **minor** version. The release lists that build's OVA/VHD links with SHA-256 checksums, links to the guides and changelog at that version, and the generated change list.
- **End-to-end test suite** in `testing/`: unattended Nutanix AHV deployment plus on-box, HTTP, collector, wizard and maintenance checks.
